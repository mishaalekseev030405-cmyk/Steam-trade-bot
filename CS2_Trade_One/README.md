# CS2 Trade One · единый бот Market.CSGO + Telegram

Самостоятельная сборка на Python 3.11+ по мотивам существовавшего `Steam-trade-bot` и открытых проектов (см. `SOURCES.md`). Один процесс управляет **сканером**, **Telegram-панелью**, **контролем бюджета**, **учётом операций в SQLite** и **проверкой статуса покупок**.

**Без ключей и Telegram-токена бот не запустится. Мы не включали в архив чужие API-ключи, пароли или готовые аккаунты.** Первая реальная покупка требует нажатия двух кнопок в Telegram. По умолчанию финансовые действия отключены.

## Быстрый запуск

### Способ 1 — Docker на Linux-сервере (рекомендуется)

1. Распакуйте архив на сервер, установите Docker + Docker Compose.
2. Создайте файл `.env` из `.env.example`: `cp .env.example .env`.
3. Впишите в `.env` ключ `MARKET_CSGO_API_KEY`, токен бота `TELEGRAM_BOT_TOKEN`, ваш числовой Telegram ID `TELEGRAM_OWNER_ID`.
4. Оставьте `DRY_RUN=true` и `LIVE_TRADING_ENABLED=false`.
5. Запустите:

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

6. Откройте личный чат с вашим Telegram-ботом и отправьте `/start`; появятся кнопки. Данные сохраняются в постоянном Docker-томе `cs2_state`.

**Важно:** не запускайте две копии одного Telegram-бота одновременно. Удалите вебхук, если он установлен, до использования `getUpdates` (см. официальную Telegram Bot API). Не передавайте никому `.env` и не публикуйте его на GitHub.

### Способ 2 — Python без Docker

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните .env и запустите:
python main.py
```

Должно быть ровно **одно** постоянно работающее приложение `main.py`; отдельно запускать `scanner.py` и `telegram_app.py` не надо.

## Параметры, заданные под ваш проект

- Бюджет: **3 000 ₽** (учёт позиций локально, это не пополнение кошелька)
- Цена предмета: **50–500 ₽**
- Минимальная **расчётная** чистая прибыль: **50 ₽**
- Минимальный **расчётный** ROI: **10%**
- Учётная комиссия при продаже: **10%**
- Продажи за 7 дней: не меньше **20**
- Позиций одновременно: максимум **3**
- Интервал сканирования: каждые **5 минут**

Цена покупки берётся **в целых копейках** из `search-list-items-by-hash-name-all` и передаётся в `buy?id=...&price=...`. Котировки `buy_order` в `/prices/class_instance/RUB.json` трактуются как **рубли** (десятичные). При нераспознанной структуре, слишком старом снимке или другой валюте бот **не торгует**. Обязательная сверка лота в момент сделки.

Оценка = `цена текущего buy-ордера × (1 - 0.10) - цена покупки`.

**Важное ограничение:** buy-ордер может исчезнуть, правила торгов/комиссии/трейд-холды меняются, поэтому это **не гарантированная прибыль** и не обещание моментальной перепродажи. Статистика `sales7d` — историческая, а не доступный сейчас объём на стороне покупателя. Скины с непроверяемыми индивидуальными премиями (`Doppler`, `Case Hardened`, `Heat Treated`, `Fade`) пропускаются, чтобы случайно не сравнить разные варианты.

## Режимы сканирования

- `SCAN_SCOPE=watchlist` — проверяет названия в `watchlist.json` (безопаснее и дешевле на старте).
- `SCAN_SCOPE=catalog` — сканирует весь доступный каталог частями `BATCH_SIZE=20`; каждый цикл сдвигает курсор в SQLite. Полный обход тысяч названий потребует много циклов. Не повышайте частоту запросов без соблюдения лимитов площадки.

Все результаты живут в SQLite, не в файлах `latest_results.json` старого репозитория. Старые JSON-файлы не удаляются и автоматически не переносятся, потому что среди них были тестовые покупки.

## Включение реальных покупок: **не делайте до проверки на сервере**

Одних данных `.env` недостаточно: сначала проверьте корректность цен и ответов API на **вашем** аккаунте и прогоните `python -m unittest discover -s tests -v`. После этого для будущего осознанного включения нужны три независимые настройки:

```
DRY_RUN=false
LIVE_TRADING_ENABLED=true
LIVE_TRADE_ACK=I_ACCEPT_REAL_MONEY_RISK
```

Только владелец в личном Telegram-чате может открыть карточку → подтвердить покупку. В случае отказа/тайм-аута/неопределённого ответа бот **никогда не отправит повторный запрос `buy` для этого лота**. Понадобится `/sync` (кнопка «Сверить покупки») и проверка истории/списаний на сайте.

**Автопокупки:** дополнительный флаг `AUTO_BUY_AFTER_FIRST=true` не активирует их сразу. Сначала необходима первая покупка вручную со статусом `CONFIRMED` после сверки, затем отдельно включите автопокупки в Telegram. Мы рекомендуем оставить это отключенным до живого тестирования.

## Риски и границы проверки

- Написано по публичной документации Market.CSGO, **не проверялось с вашим действующим ключом** и не совершало реальных сделок.
- Поведение статусов `stage=1/2/5` взято из документации API. При неясном ответе система запрещает новые покупки, а не угадывает результат.
- Telegram-команды обрабатываются только в личном чате владельца. Идентификаторы и токены должны храниться **только** в `.env` или секретах хостинга.
- Автоматическая продажа/вывод на Steam и покупка с дальнейшей реализацией между площадками **не внедрены**: перед включением нужен аудит переходов прав собственности, платы и блокировок трейдов.
- Хранилище: SQLite с устойчивым ID операции. Регулярно делайте резервную копию тома `cs2_state`; не удаляйте его при обновлении контейнера.
- Этот архив **не меняет** исходный GitHub-репозиторий; переносите сначала в отдельную приватную ветку/репозиторий.

## Проверка без доступа к рынку

```bash
python -m unittest discover -s tests -v
```

Тестируются расчёты, разделение копеек/рублей, проверка реальной цены, запрет повторных сделок, неизвестные результаты и работа с API на локальных подставных HTTP-ответах. Это не интеграционное тестирование с Market.CSGO.
